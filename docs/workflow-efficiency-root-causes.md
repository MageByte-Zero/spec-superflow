# 执行成本与恢复缺陷复核

基线：PR #122，`streamline-execution-flow` 的 `9c118a4`。本次未用被审查工作流驱动修复，也未派发子代理。

## 根因与改动

| 根因 | 后果 | 修复 |
| --- | --- | --- |
| 文档把每个决策点当成新问答，规划要求盲读子代理 | 固定等待、重复上下文和额外交接 | 同一决定复用已有授权；规划一次自查；委派须明确选择 |
| 最终审查沿用增量 wave 修复规则 | 完整复审被拒绝，或只审最后一次提交 | 最终审查固定隔离起点至当前 HEAD，修复轮次也覆盖完整变更；空 diff 不能通过 |
| 三次失败后的裁决状态未进入恢复 blockers | 恢复继续指向审查，反复重试 | 输出人工裁决阻塞；明确授权后允许有新提交的一轮复审 |
| 丢失 direct Hotfix 收据被当成 legacy | 短路径突然要求整套规划 | 持久化路径变体，缺收据只要求恢复该路径证据；旧版本未记录变体的遗留目录仍须人工核实 |
| 诊断转换重写批准哈希，恢复重复读取执行证据 | 掩盖合同变化、增加读取、错误重建计划 | 保持批准哈希；同时检查规划与合同；恢复共用一次快照，分别回到规划或契约阶段 |
| closing 视为绝对终态，但物理 finish 可能失败 | 收尾失败后无法回调试 | 仅记录 verify-pending 时允许诊断恢复；已完成和放弃仍为终态 |
| finish 跨进程只凭 HEAD/环境复用验证 | 忽略依赖变化，错误清理隔离目录 | 每次未完成的 finish 调用验证一次，已完成调用幂等返回 |
| worktree 自动创建、重试复制覆盖、目录来源未验证 | 多目录漂移、证据丢失、错误位置继续实现 | 默认当前目录特性分支；worktree 显式选择；重试保留已有文件；恢复核对实际目录和分支 |
| 分支模式验证失败停留主分支 | 后续修复可能写错分支 | 工作区干净时返回特性分支；测试产生改动时保留现场 |
| OpenCode 普通会话注入完整工作流 | 与任务无关的固定 token 开销 | 无活跃变更不注入；其余入口只提供受用户意图约束的短指针 |

## 默认执行约定

Native (`inline`) 连续执行，默认一次 final review。任务数量和上下文长度不能自动授权 SDD。仅按当前任务读取实现/审查提示，复用已展示且未改变的决定，不逐工件询问继续。共享接口在实现前做一次有界核对，避免到后半程才发现规划不可实现。

隔离默认是特性分支，worktree 仅 `--worktree` 显式创建。保留旧 worktree 的恢复与安全清理能力，避免升级后已有任务无处恢复。创建失败不能偷偷接管同名分支，也不能自动换成另一种隔离方式。

门禁区分建议与证据：模式偏好、可复用授权不应产生新对话；丢失/损坏证据、错误目录、失败验证不能伪装成功。用户可以作出新决定、修订范围或放弃；这不等于生成不存在的验证通过记录。阻塞应给出具体恢复方向，不能要求代理反复执行原命令。

## 验证与限制

`tests/lib/efficiency-boundaries.test.mjs` 使用真实临时 Git 仓库复现审查截断、空 diff、修复轮次、裁决、丢失收据、终态恢复、目录漂移、初始化重试与验证缓存问题。已有测试覆盖短路径、guard、安装器、子模块和平台输出；运行完整构建与测试后再交付。

用户提供的会话统计表显示大量时间用于等待决策和模型/子代理运行；这些截图是诊断线索，不是当前版本的性能基准。本次可确认消除了具体重复动作和错误恢复路径，不宣称已测得某个 token 降幅，也不承诺无 bug。Windows 原生安装和完整长会话性能仍需对应环境验收。

借鉴本地 OpenSpec 的按需读取和任务进度继续机制，以及 Superpowers inline 执行中的有界接口预检与持续执行原则；不引入其子代理要求或额外工作流。

## 结构性简化（后续改动）

新任务只用 direct/planned 两个入口。direct 的生命周期是 start → complete；planned 在一次具体计划批准后 start → 实现/审查 → complete。isolate 和实际 review 是必要的 Git/质量操作，不用来生成新的用户问答。普通调试不切状态。

planned 默认两份手写文件 proposal/tasks，specs/design 按需。执行 JSON 由 CLI 从 tasks 生成，承担批准与计划的权威记录；Native 默认值不再要求推荐凭据，派生状态缓存不再互相卡住。旧八状态仅为已有任务兼容保留，没有自动迁移失败链。

complete 自己执行指定验证一次；不要先再跑相同全量验证。明确的风险接受记录为 accepted-risk，保留失败和未完成任务，结束交付但不自动合并。真实工作中的 token/耗时仍须实测；命令数量、手写文件和强制问答的减少是结构性变化，不是声称的性能百分比。
